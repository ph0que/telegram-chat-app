# Саморевью и ретроспектива

## О проекте

Небольшое чат‑приложение: фронтенд на React + TypeScript (Vite), бэкенд на FastAPI.[web:179] Пользователь видит список сообщений и может отправлять новые, общение идёт через REST API (`GET /messages`, `POST /messages`).[web:179]

**Финальный статус деплоя:**

- ✅ Frontend: Vercel → https://telegram-chat-app-97tg.vercel.app
- ✅ Backend: Render → https://telegram-chat-app.onrender.com
- ✅ Фронт и бэк связаны через `VITE_API_URL` и CORS, прод полностью рабочий.[web:179]

---

## Что делал в этом проекте

- Спроектировал простую архитектуру: отдельные папки `backend/` и `frontend/`, отдельные команды запуска и деплоя.[web:179]
- Реализовал REST API для сообщений на FastAPI (получение списка и отправка нового сообщения с валидацией через Pydantic).[web:179]
- Собрал интерфейс на React + TypeScript: список сообщений, форма отправки, загрузка данных с API, обработка ошибок и состояний загрузки.[web:179]
- Настроил переменные окружения через `VITE_API_URL`, чтобы легко переключаться между локальным и прод‑бэкендом.[web:179]
- Задеплоил фронтенд на Vercel и бэкенд на Render, связал их между собой.[web:179]
- Оформил документацию: PLAN.md, README.md с инструкциями по запуску и деплою, этот REVIEW.md.[web:179]

## С какими трудностями столкнулся

### 1. CORS и запросы с Vercel к Render

**Проблема:**  
Фронтенд на Vercel не мог обратиться к бэкенду (сначала к localhost, потом к Render) из‑за CORS‑ошибок и неправильного URL API.[web:179]

**Что сделал:**

- Вынес адрес API в переменную окружения `VITE_API_URL` и настроил её в Vercel на `https://telegram-chat-app.onrender.com`.[web:179]
- Добавил в `backend/main.py` `CORSMiddleware` и явно указал домен фронтенда `https://telegram-chat-app-97tg.vercel.app` в списке `origins`.[web:179]
- Проверял ответы через DevTools → Network, пока не исчезли CORS‑ошибки и запросы не стали стабильными.[web:179]

**Вывод:**  
Даже у простого REST API на проде CORS и правильный URL фронта к бэку — критичная часть, без этого “всё работает локально, но не в проде”.

---

### 2. Настройка деплоя FastAPI на Render

**Проблема:**  
Нужно было корректно запустить FastAPI на Render: подобрать команду запуска, порт, зависимости.[web:179]

**Что сделал:**

- Описал зависимости в `requirements.txt` для backend.[web:179]
- Настроил Web Service на Render с командой вида `uvicorn main:app --host 0.0.0.0 --port 10000` (порт задаёт Render).[web:179]
- Проверил, что эндпоинты доступны по публичному URL и отвечают корректно, до подключения фронта.[web:179]

**Вывод:**  
Важно сначала убедиться, что бекенд живёт и отвечает по прод‑URL, и только потом подключать к нему фронтенд.

---

### 3. Git, мусорные файлы и чистый репозиторий

**Проблема:**  
В репозиторий пытались попасть `venv`, `node_modules`, `.env.local` и кэш‑файлы Python, мешали коммитам и статусу git.[web:179]

**Что сделал:**

- Обновил `.gitignore`, чтобы исключить `venv/`, `node_modules/`, `*.pyc`, локальные env‑файлы.[web:179]
- Почистил рабочее дерево, оставил в репозитории только то, что действительно нужно для сборки и деплоя.[web:179]

**Вывод:**  
Чистый `.gitignore` сильно упрощает жизнь: меньше шума в `git status`, меньше риска случайно закоммитить секреты или тяжёлые папки.
